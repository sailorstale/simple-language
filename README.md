# Simple Language

**Скил для русского** | [English skill](README.en.md)

Claude перестаёт писать плотными абзацами с терминами и начинает объяснять обычными словами. Правила ставятся в Claude Code как плагин один раз, и дальше он держит их сам, без напоминаний в каждом разговоре. Язык он определяет по твоему сообщению: на русское отвечает по русским правилам, на английское по английским.

## Что меняется в тексте

**Веди с главного.** Первое предложение отвечает на вопрос, а подробности идут после него.

> 🚫 «Идемпотентный импорт с детерминированными id и upsert родительских записей позволяет…»
>
> ✅ «Данные загрузились. Можно перезапускать сколько угодно, повторов не появится.»

**Верни глаголу работу.** Из существительных вроде «осуществление» и «проведение» вынули действие, и фраза стала казённой.

> 🚫 «Является организацией, осуществляющей помощь людям.»
>
> ✅ «Помогает людям.»

**Дай числу смысл.** Голая цифра ничего не говорит, а доля читается сразу.

> 🚫 «Собрано 39% плана.»
>
> ✅ «Собрано примерно 4 части из 10, то есть меньше половины того, что планировали за год.»

## Что нужно иметь

- **Claude Code**, причём такой версии, которая понимает плагины, скилы и хуки.
- **Node.js** нужен только проверщику, потому что скил и хук работают без него (мы запускали проверку на Node 24).
  - Проще всего сказать Claude «поставь мне Node.js», и он сделает это сам.
  - Второй способ — скачать установщик с сайта [nodejs.org](https://nodejs.org) и нажать кнопку LTS.
  - Третий способ подойдёт тем, у кого на Mac стоит Homebrew: `brew install node`.
  - Наш установщик сам проверяет, есть ли Node, и печатает эту же подсказку.
- **Папку `~/.claude`** — она появляется сама после первого запуска Claude Code.

## Установка

Набор ставится как плагин Claude Code. Две команды в сессии Claude, и он сам заберёт скилы и хуки с GitHub:

```
/plugin marketplace add sailorstale/simple-language
/plugin install simple-language@simple-language
```

Первая команда добавляет наш каталог плагинов, вторая ставит из него сам плагин. Ничего копировать и прописывать в `settings.json` не нужно: хуки живут внутри плагина и включаются вместе с ним. Обновление и удаление делает тот же `/plugin`.

Дальше идут два запасных способа на случай, если плагины тебе не подходят или хочешь понять, что именно происходит внутри.

### Установщик

Склонируй репозиторий и запусти скрипт. Он скопирует оба скила и оба хука в `~/.claude` и подключит хуки в настройках.

```bash
git clone https://github.com/sailorstale/simple-language.git
cd simple-language && ./install.sh
```

Установщик не трогает чужие записи в `~/.claude/settings.json`. Он добавляет свои строки рядом с ними, а старый файл сохраняет копией под именем `settings.json.bak`. Если хуки уже подключены, второй раз он их не добавит, а записи прежних версий с двумя языковыми хуками заменит на одну. Для правки настроек ему нужен `python3`, и без него он попросит вписать запись руками.

### Вручную по шагам

1. **Скопируй скилы** в папку скилов Claude:

```bash
cp -R skills/pishi-prosto skills/plain-english ~/.claude/skills/
```

2. **Скопируй хуки** и сделай их исполняемыми:

```bash
cp hooks/write-simply.sh hooks/check-prose-on-write.sh ~/.claude/hooks/ && chmod +x ~/.claude/hooks/write-simply.sh ~/.claude/hooks/check-prose-on-write.sh
```

3. **Подключи хуки** в `~/.claude/settings.json`: добавь блок из [settings-snippet.json](settings-snippet.json).

> Если раздел `hooks` в файле уже есть, впиши записи `UserPromptSubmit` и `PostToolUse` внутрь него. Второй раздел `hooks` заводить не нужно.

После этого перезапусти сессию Claude, чтобы он подхватил новые хуки и увидел скилы.

## Как проверить, что заработало

Три способа, от самого быстрого к самому наглядному.

1. **Запусти проверку на любом файле.** Если она печатает отчёт, скил и его программа лежат на месте. При ручной установке путь такой:

```bash
node ~/.claude/skills/pishi-prosto/scripts/prose-check.mjs "путь/к/файлу.md"
```

Плагин лежит в другом месте, и проще спросить у Claude: «прогони проверку pishi-prosto по этому файлу».

Отчёт выглядит так:

```
README.md — находок: 1

  Слишком длинное предложение — 1
    строка 12: Скрипт читает документ и показывает места, где нарушены правила…
      ↳ 33 слов в одном предложении — разбей на два-три
```

2. **Посмотри список хуков.** Команда `/hooks` в сессии Claude показывает подключённые хуки, и среди них должен быть `write-simply.sh`. При ручной установке та же запись стоит в `~/.claude/settings.json` в разделе `UserPromptSubmit`.

3. **Начни новую сессию и попроси Claude объяснить что-нибудь сложное.** Ответ должен идти обычными словами и короткими предложениями, а плотный абзац с терминами означает, что хук не подключился.

## Как это работает

Набор состоит из трёх частей, и каждая делает свою работу.

- **Хук** из папки `hooks/` подкладывает Claude короткую выжимку правил при каждом твоём сообщении, чтобы они не забывались в обычном разговоре. Язык выжимки он выбирает по сообщению: если в нём есть кириллица, приходит русская, иначе английская. Пути к файлам, ссылки и код он при этом не считает, поэтому «открой src/App.tsx» остаётся русским сообщением.
- **Скил** из папки `skills/pishi-prosto/` хранит все правила целиком и открывается, когда Claude берётся за большой текст или когда ты зовёшь его командой `/pishi-prosto`. Английский скил `plain-english` лежит рядом и работает так же.
- **Проверщик** из папки `skills/pishi-prosto/scripts/` читает уже написанный файл и показывает места, где правила нарушены.
- **Второй хук** из папки `hooks/` запускает эту проверку сам, как только Claude записал документ, и отдаёт находки обратно ему.

Три части закрывают разные дыры. Хук приходит всегда, но несёт только девять главных пунктов. Скил объясняет подробно, зато Claude открывает его редко. А проверщик ловит то, что всё равно проскочило, потому что автор своих ошибок в тексте не видит.

### Чем это лучше, чем просто попросить Claude писать проще

Устная просьба живёт несколько сообщений и забывается, потому что разговор уходит вперёд и старые указания тонут в нём. Хук приходит с каждым сообщением и поэтому не выветривается. К тому же в просьбе помещается одна-две мысли, а в скиле лежат правила с примерами и разбором, чего в просьбу не вместить.

### Сколько стоит хук

Хук платится за каждое твоё сообщение, и его копии остаются в истории разговора. Поэтому он работает экономно и шлёт полный свод редко.

- **Полный свод** уходит один раз, первым сообщением сессии на этом языке.
  - В нём 1823 знака, и он несёт только то, что проседает в разговоре.
  - Тонкостей оформления в нём нет, потому что они живут в скиле и нужны при работе с документом.
- **Короткое напоминание** на 384 знака идёт во все остальные ходы, и это примерно четверть полного текста.
- **Служебные сообщения не получают ничего.** Сюда попадают команда со слешем, путь к файлу, ссылка и короткие ответы вроде «да» или «ок».

На разговоре в 50 сообщений выходит около 17 000 знаков. В первой версии хука выходило 133 000, то есть теперь расход меньше примерно в восемь раз.

Поведение меняется переменными окружения:

| Переменная | Что делает |
|---|---|
| `SIMPLE_LANGUAGE_LANG=en` | не угадывать язык, а всегда слать английский свод (или `ru` для русского) |
| `SIMPLE_LANGUAGE_FULL_EVERY=10` | вернуть повторы: полный свод придёт каждым десятым сообщением |
| `SIMPLE_LANGUAGE_MODE=full` | всегда слать полный свод, как было в первых версиях |
| `SIMPLE_LANGUAGE_MODE=off` | молчать и не слать ничего |
| `SIMPLE_LANGUAGE_CHECK=off` | не проверять документы после записи |
| `SIMPLE_LANGUAGE_CHECK=full` | показывать находки по всему файлу, а не только в правленых строках |

Чтобы угадывать язык и считать сообщения, хуку нужен `python3`. Без него он шлёт полный свод каждый раз, а язык берёт из переменной `SIMPLE_LANGUAGE_LANG`, и без неё русский.

### Проверщик умеет читать и твой текст

Скил создан ради того, что пишет Claude, но проверщику всё равно, кто написал файл. Дай ему свой документ, и он покажет находки так же. Это побочная возможность, и работает она только по твоей команде.

> Скилы подхватит любой агент на Claude Code, а хук работает только в самом Claude Code.

## Сколько тут правил

Правил сорок четыре про язык и ещё шестнадцать про то, как оформлять текст. Вот пять из тех, что отвечают за оформление.

- **Абзац держится в двух-четырёх предложениях**, а новый топик или шаг начинается с нового абзаца.
- **Пункт списка помещается в одно предложение**, и если он длиннее, значит это был абзац, а подробности идут вложенными подпунктами.
- **Списка из одного пункта не бывает**, потому что список показывает, что пунктов несколько и они равноправны.
- **Структуру держат заголовки**, выделенная жирным строка их не заменяет, а уровни идут по порядку: за `##` следует `###`.
- **Текст ссылки называет то, куда она ведёт**, поэтому слова «здесь», «тут» и «подробнее» в ссылку не ставят.

Остальные правила разбирают картинки и подписи к ним, устройство таблицы, работу каждого приёма оформления и доступность текста для тех, кто читает его не глазами.

## Источники

Правила не придуманы с нуля. Они собраны из руководств, которыми пользуются государства и крупные компании.

- **Правила языка** сделаны по мотивам инфостиля Максима Ильяхова: сервис [Главред](https://glvrd.ru) и книга «Пиши, сокращай».
- **Правила форматирования** опираются на руководства [Microsoft](https://learn.microsoft.com/en-us/style-guide/welcome/) и [Google](https://developers.google.com/style), а также на исследования [Nielsen Norman Group](https://www.nngroup.com/articles/how-users-read-on-the-web/) о том, как люди читают с экрана.

Английский набор живёт по своим источникам и не повторяет русский правило в правило. Языки устроены по-разному, поэтому мы держим наборы похожими там, где это уместно, и расходимся там, где норма своя.

## Как удалить

Плагин убирается одной командой в сессии Claude:

```
/plugin uninstall simple-language
```

Ручную установку убирает скрипт. Он удаляет скилы, хуки и записи в настройках, включая хуки прежних версий:

```bash
cd simple-language && ./uninstall.sh
```

Копию старых настроек он сохранит рядом под именем `settings.json.bak`. После этого перезапусти сессию Claude.

## Если правишь правила

В папке `tests` лежат файлы-образцы с известными нарушениями и ожидаемый список находок. Одна команда прогоняет обе программы по ним и говорит, сошёлся результат или нет:

```bash
node tests/run.mjs
```

Та же проверка идёт при отправке в облако: файл `.github/workflows/prose.yml` прогоняет тесты и проверяет изменённые документы прямо в GitHub.

Прогон проверяет не только образцы поиска. Он читает манифест плагина, ставит набор в песочницу и удаляет его, смотрит, целы ли чужие настройки, и запускает оба хука на русских и английских сообщениях.

Запускай её после любой правки образцов поиска. Образцы легко сломать незаметно: правишь одно правило, а перестаёт срабатывать соседнее. Если находка изменилась намеренно, обнови файл `tests/expected.json`.

## Как проверить, что плагин помогает

Тесты выше проверяют проверщик и хуки по отдельности. Эвалы плагина смотрят на результат целиком: Claude получает обычный запрос, а потом судят, что он написал. Запросы лежат в папке `evals/`, по одной папке на каждый. В ней `prompt.md` с сообщением и папка `graders/` с проверками: регулярки по ответу или файлу, факт вызова скила и рубрика для модели-судьи.

Запросов семь. Два спрашивают про технический термин, по-русски и по-английски. Два дают Claude число с процентом. Два просят документ через Write. Последний просит код, и там плагин не должен мешать.

Запускать из корня репозитория, нужен Claude Code 2.1.269 или новее:

```bash
claude plugin eval . --allow-tools Write
```

Каждый запрос идёт три раза с плагином и три раза без него. В отчёте есть колонка Δ, и она показывает, что плагин добавил к результату. Прогон стоит денег, потому что это настоящие вызовы модели на твоём аккаунте. Один запрос без базовой линии обходится дешевле:

```bash
claude plugin eval . --case ru-explains-jargon --runs 1 --ablation none
```

Грант `--allow-tools Write` нужен только двум запросам про документ, без него они закончатся ошибкой. Отчёты ложатся в `evals/results/`, и эта папка не попадает в git.
